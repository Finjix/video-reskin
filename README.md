# video-reskin

版本 `0.0.1`（见 `plugin/plugin.json`）。批量把视频转换画风的 OpenAI 插件，主要面向 ChatGPT / Codex 的本地执行环境，支持 Windows 10/11 x64。默认风格是“写实版材质，风格不变”，成片固定为 1080p、24fps，会去掉片尾尾板，游戏 logo 和底部警示语按原片原样保留（拼接时从原片逐帧贴回），保留原声。工作流以“画面稳定、接缝无跳变、成本低”为先，写实程度适度即可。

## 工作流

AI 阅读 `plugin/skills/video-reskin/SKILL.md` 后通过统一入口操作。所有发给模型的提示词（GPT Image、Seedance、Gemini）统一用英文：模板、程序拼出的句子，以及 edits 里的材质、去除项、`extra` 和 `redo --prompt` 的纠正语句；报告和给用户的说明仍用中文。

```powershell
& "plugin/scripts/video_reskin.cmd" --help
& "plugin/scripts/video_reskin.cmd" auth --key <Winky API key>
& "plugin/scripts/video_reskin.cmd" login
```

`init` → `analyze` → `lint` → `plan` → `run`（关键帧和主体参考图，停下来看图）→ `run`（逐段检查的渲染：每段渲完 Gemini 看视频、主 agent 看静帧，放行后才渲同镜头的下一段；每个源渲完马上拼接、审片、查接缝）→ `checks` 列出待查卡片，`accept` 放行或 `redo` 重做 → 再 `run`。各步骤也可以单独执行（`keyframes`、`render`、`assemble`、`review`；`preview` 只在需要时预览个别时刻），`cost` 查看花费；用户要原片对比时，`compare` 生成左原片、右成片的 `<名称>_写实_对比.mp4`；重做一版后可以用 `compare --with <旧成片> --labels 原版 旧写实版 新写实版` 生成三栏对比。

1. **分析**（`analyze`）：识别镜头切换，找出尾板起点候选和静止叠加物（logo、警示语、HUD），生成联系表。AI 看图后写 edits 文件，内容包括保留区间、画面里的真实材质、要去除的元素（只在用户要求时才写）、需要保留原样的屏幕 UI（`ui`：计数器、按钮、字幕、横幅、游戏 logo、警示语，逐条写明位置、引号里的原文、颜色和数字变化，由模型照着画；数值会变的计数器写 `values`（`[[秒, "数字"], ...]`，从原片逐帧读出），程序按每个片段自己的时钟把数值和变化时刻写进提示词——时刻写在描述文字里没用，片段不知道整片的秒数（GOF3D10374 的金币计数被画成 280，原片是 200）；会动的数字、弹出或飞入的文字等特效标 `dynamic`，允许运动时有少量模糊和拖影，静态的文字、logo、警示语不允许模糊、乱码、边缘发虚）、需要稳定的主体（`subjects`，见下）和锚点帧。插件只转化游戏玩法画面：素材里混进来的真人/实拍片段（GOFCN67484 开头车里的真人和熔岩、GOFCN5456 开头的雪地公路、GOFCN7427 开头的雪林，GOFCN60010/63256 开头贴在木头上的真人脸）写进 `live`，由 `lint` 帮忙找出；这些区间单独成段，成片里直接用原片画面，不做关键帧、不送 Seedance、审片也不算问题。
2. **分段**（`plan`）：Seedance 2.5 能一次编辑 4–30 秒，30 秒内画质保持稳定，所以分段尽量少、尽量长，优先在硬切处断开。超长镜头会平均切分，断点选在画面最静止的位置，后一段多渲染 1 秒作为重叠区。
3. **关键帧**（`keyframes`）：写实预设只把材质、纹理和光影换成真实世界的样子，物体和角色的造型、比例、布局、位置、数量、动作和固有颜色都不变（Q版人物仍是Q版造型，只是衣服、皮肤和头发变成真实材质）。用户给了参考图或参考视频时，edits 里的 `style_ref`（视频某一帧，可裁掉 logo 和警示语）作为锚点的第二张图，只学习它的质感，不复制内容。参考飞书案例，先用 `gpt-image-2.6-sunburst` 把锚点帧“转化为写实版材质，风格不变”，再以锚点为参考，生成每个镜头首段的首帧。
   **主体参考图**（`subjects`）：做计划时先找出相对参考帧会新出现的东西（镜头中途入画的道具、车辆、人物）和需要保持稳定的东西（主角、反复出现或频繁移动的角色和物品），`lint` 起草，`plan` 在 `reports/plan.md` 里逐段列出每段带哪些参考图、哪些主体是参考帧之后才出现的、哪些中途入画的物品还没有参考图。每个主体从原片裁 1–3 张，以锚点为风格参考生成一张多视角写实参考图（同一张图里排几个视角：`2d` 正面加左右侧面，`2.5d` 游戏固定 45° 俯视角的四个方向，`3d` 正面、3/4、侧面、背面，按视频的镜头类型选），浅灰背景、只有这个主体。镜头首帧的生图带上画面里主体的参考图；Seedance 的参考图是关键帧加本段出现的主体参考图（每段最多 4 张），提示词写明各主体在段内的出场时间。横竖版共用同一套参考图。图片统一走 Lumos 图生图接口（用 Lumos 登录态，不用 Winky key），质量 `high`、分辨率 2K。
4. **视频编辑**（`render`）：在 Lumos 上逐段调用 Seedance 2.5（`doubao-seedance-2-5-260628`），模式是 `video_edit`，分辨率固定 1080p，送去的片段也是 1080p（Lumos 上这个模式最多 30 张参考图）。同一镜头内的各段串成一条链：首段以关键帧作参考；后面每段的输入片段依次是：这个镜头开头 0.5 秒的原片（参考图是这个镜头的关键帧，Seedance 从“第一帧 → 参考图”这一对里读出要做的改动）、上一段 AI 结果的最后 1 秒（按原片时钟拉伸回去），再是本段自己的原片；拼接时去掉开头那 0.5 秒，前一段一直播到这 1 秒结束，再直接切到本段自己的画面，颜色按切点两侧的画面匹配（Seedance 会给复制的那 1 秒重新调色，在里面切换会多出一段颜色不同的画面）。只把上一段结果放在最前面、参考图也用它时，Seedance 读出的改动是“什么都不改”，GOF3D10012 在 26.4 秒处树又变回卡通、河水变浅，logo 也没删。1080p 那批只给参考图，13 个镜头内接缝里有 8 个按现在的标准测出明显跳变（GOF3D10374 在 33.6 秒处原木、水面和纹理都变了）。**现在默认不去 logo 和警示语**：lint 把它们起草成 `ui` 条目，提示词让模型按描述原样画出，审片逐字核对。以下是用户要求去 logo 时的经验：logo 留在送去的片段里，由提示词让 Seedance 删除：GOF3D10012 在 720p 下所有角落都删干净了，没有模糊块。链式的后一段开头那 1 秒来自上一段结果（已经没有 logo），程序会把原片的 logo 像素贴回这 1 秒，让 logo 从第一帧起就在，否则 Seedance 会把中途“出现”的 logo 当成新内容保留。程序先抹掉字母再送（`"wipe": "before"`）的做法，Seedance 每次都留下模糊块（还有一次自己重新画出了游戏 logo），不再用于 logo。画面最底边的警示语无论点名还是抹掉都会保留，干净的去法只有把原片副本的底边裁掉（约 6% 放大），需要先征得用户同意。不同镜头、不同视频之间并行，可以断点续跑。
5. **拼接**（`assemble`）：
   - Seedance 返回 24fps 视频，时长比原片段略短，每段按原时长精确拉伸。
   - 同一镜头内的接缝先做最小二乘调色，再在共享的那 1 秒里找两版最相近的一帧，用 2 帧切换，不做淡入淡出（两版不同时，长一点的过渡看起来就是渐变）。每个接缝都测两处：切换点两版的差异，以及后一段自己的画面开始处的逐帧变化；结果分为 clean、slight、visible 三档，标准比以前严（差异超过画面自身运动 2.2 倍也算明显），并生成接缝对照图。
   - （用户要求去 logo 时）每个去 logo 的角落都会测一次：被抹掉的字母区域里剩下的细节和周围场景相比的比例，低于 0.4 判为 `smeared`（模糊涂抹块），低于 0.6 判为 `soft`。1080p 那批糊掉的角落测得 0.1–0.38，干净的约 1.05。
   - HUD、屏幕固定的文字和 UI、游戏 logo、警示语都由模型绘制，拼接时不再从原片贴回或由程序烧录（`hud`、`overlays` 字段已取消，写了会报错）。edits 的 `ui` 条目逐条写进关键帧和视频提示词（只在该元素出现的时间内），并说明它是平面 2D 层、不做材质和光影、逐字照抄、只画一份、逐帧稳定、数字只按原片变化。
   - 最后铺上原片对应区间的音频，输出 1080p、24fps 的 H.264。
6. **质检**：分两层，看的东西不同。Gemini 看原生完整视频（不抽帧，每格保持成片尺寸 1080p、`crf 18`，`MEDIA_RESOLUTION_HIGH`：实测默认每帧只用 66 token，HIGH 是 264 token），管整体、运动和连续性；主 agent 看全尺寸静帧（JPEG 95，一刻一张，原片在上、成片在下，竖版左右），管细节。每项检查写一张卡片，列出全部静帧、要看什么和回报格式；能用子代理时每张卡交给一个子代理并行看，主 agent 在同一批静帧上确认后再 `redo` 或 `accept`。接口单个内联视频上限 256,000,000 字节（2026-11-06 实测），超出时自动逐步提高 crf。
   - **逐段检查**（每段渲完马上做，`review/segments/<id>-<Kxx>/card.md`）：Gemini 看本段与原片完整并排（6 fps）；前一段已渲染时，再看两段的 2×2 网格（上排两段原片、下排两段成片），查色差、亮度差、场景和主体变化，原片自己的变化不算；两次调用并行。主 agent 看本段每 2 秒一张对原片的静帧，以及与前一段同一段内偏移、每 2 秒一张的对比静帧。免费测量（接缝、去 logo 角落）保留。同镜头的下一段要等主 agent 放行（`accept --segment`）或打回（`redo`）才开始渲染；测出明显接缝、模糊角落或 Gemini high 问题的卡标为 HELD，放行必须写理由。等待的链会让出并发名额，放行后一分钟内接着渲；`run --wait-checks` 放后台、配合 `checks --wait` 可以边渲边审。
   - **接缝检查**（每轮审片对拼好的成片做，`review/seams/<id>-<Kxx>/card.md`，紧挨实拍段的接缝除外）：Gemini 直接看接缝前后各 2 秒、共 4 秒的原片 | 成片片段，按成片原帧率，查跳变、渐变、色差、亮度差、场景和物品变化；主 agent 看前后 2 秒内每 1 秒一张，外加切换前最后一帧和切换后第一帧（后一段自己的画面开始得更晚时也加那一刻）。逐一 `accept --seam` 放行，重新拼接后要重新放行。程序对整条视频逐帧算的“观感变化”（扣除镜头位移和原片自身的变化）照旧，GOF3D10012 26.4 秒那种灰度测量漏掉的接缝靠它和全尺寸静帧抓。
   - **整片审查**：原片和成片并排交给 `gemini-3.8-flash`，各段已经单独查过，所以侧重只有整片才看得出的问题：跨段、跨镜头的观感和主体漂移、尾板、新增文字。写实度只作为时间线报告（5 分像真实相机实拍），2 分及以下才算 medium 问题；不再为写实度返工。
   - **一致性检查**（`identity`）：按 edits 里的 `subjects` 逐个跟踪（没写时 Gemini 自己挑主角和最多 3 个主体），和风格关键帧逐对比较。
   - **保留元素检查**：带 `box` 的 `ui` 元素逐字比对（每个元素 8 个时刻，原片在上、成片在下，按原像素出图）。静态元素的乱码、模糊、边缘发虚、重影、移位、变色、缺字一律 high；`dynamic` 元素运动时的模糊和拖影只算 low，乱码和数字错仍然算。修复要重渲：关键帧上就错了，改准 `ui` 描述后 `plan`、`redo --keyframe`；只在视频里错，用 `redo --prompt` 点名该元素和原文重做该段。两次仍不对就报为未解决，不再烧录。
   - **去 logo 区域检查**（`gemini-wipe`，只在有带 `box` 的去除项时）：每个带 `box` 的去除项按时间抽 8 个时刻，原片和成片的该角落上下对照，Gemini 找残留字母、复制进来的物体和糊斑。
   - **已删掉的环节**：旧的接缝 10fps 近看、Gemini 看接缝静帧对、Gemini 对问题静帧的二次分诊（这些现在由逐段和接缝检查的卡片、主 agent 的静帧确认代替）。
   - 只有观众一眼能看到的问题才返工：明显接缝、模糊或残留的 logo、静态文字或 logo 模糊乱码、新增文字、变形/消失/多出来的物体、主体前后不一致、主要物体颜色错。medium 和 low 问题写进总结。不限轮数，一直审到没有明显瑕疵、`checks` 也没有待查卡片为止（`review_rounds` 默认 0；工作单里写正数才封顶）。

成片默认放在桌面的 `视频换风格_YYYYMMDD_HHMMSS/` 下，同级只有一个任务目录 `temp/`。文件名默认是 `<原名>_写实.mp4`，工作单 `options.name_suffix` 可以改后缀（如 `"_写实版"`）。

## 省钱和提速

1080p 那批 9 条视频（约 500 秒）生了 427 张图（393 张是预览图），提交了 87 次 Seedance、共 1952 秒（首次 547 秒，其余是返工、改计划、链式连带、改 logo 框和补丁）。现在的做法：

- **固定 1080p、24fps**：Seedance 按 1080p 渲染，成片 1080p、24fps（就是 Seedance 的帧率）；GPT Image 质量 `high`（不用 `max`）、分辨率 2K。
- **不再自动出预览图**：`run` 只做关键帧（每个源一个锚点加每个镜头的首帧）。`preview --only S01 --at T` 只在关键帧看不到的时刻有疑问时用，每次最多 4 张。
- **去掉 midframes 和局部补丁**：预览图不再作为参考图交给 Seedance（它把预览图的颜色错误带进视频）；`patch` 已删除（每个补丁多两个接缝）。
- **写实度适度**：只换材质、不改造型，不追求“更真实”，不为写实度返工；身份一致性检查只在审片时做一次。
- **逐段检查当场拦住问题**：同一镜头里后一段从前一段的结果接着画，后面的问题打回会连带重渲整条链。所以每段渲完、下一段开始前，Gemini 看视频、主 agent 看静帧，放行后才接着渲；问题在这一段就重做，不连带后面的段。
- **主体参考图一张多视角**：每个主体只花一张图，多个视角画在同一张里；横竖版共用。
- **横竖版只写一份 edits**：竖版不是横版的裁切（镜头拉远、重新构图，两版各有对方看不到的部分），Seedance 两版都得渲。竖版写 `"like": "<横版 ID>"`，只填自己的去除框和 `ui` 条目（位置不同），其余（保留区间、材质、`extra`、锚点时间、断点、画风）跟横版走；时间跨度相同的段还会带上横版的 `redo --prompt` 纠正语句。`run` 会等横版成片审完、没有待重做的段再渲竖版，横版上踩过的坑不再在竖版上花一遍钱（`--only` 可以立刻渲）。内容相同（md5 一样）的文件只做一次。
- **先定好 edits 再渲染**：改 logo 框、保留区间或断点会重渲相关段（那批为此花了 436 秒）。
- **审片不限轮数**，审到没有明显瑕疵为止，但只返工观众一眼能看到的问题；同一段返工两次还在的，换做法（改材质措辞、分时段、改断点）而不是重复返工。
- **已接受的问题不再拦**：`accept` 放行的检查结果和原因会告诉后面的逐段检查和审片。
- **不重复付费**：提交只发一次，回复丢失时先按本次上传的 `media_id` 查历史；同一任务不允许两个渲染同时跑。
- **纠正提示词**：`redo --prompt` 的纠正语句会随重做累加；只点名要变的部件和要保持的东西，写错了用 `--replace-prompt` 替换。
- **断电恢复**：JSON 状态先落盘再改名；`work/` 里读不出的缓存会自动重建；已提交的生成在重跑 `run` 时接着取。
- **记账**：每次付费调用写入 `state/ledger.jsonl`（首次、redo、上游连带、自动重试、改计划……），`cost` 汇总。
- **流水线**：最长的链先渲；每个源的段一齐就拼接、审片，不等整批。

## 账号

- **Lumos 登录**：`login` 会用隐藏的 Edge（或 Chrome）打开 Lumos 登录页，把飞书二维码保存成图片并弹出。用户扫码后，插件只保存 refresh token，用它换取访问令牌。
- **Winky API key**：通过 `auth --key` 保存，只用于 Gemini 审片。
- **存储方式**：两者都用 Windows DPAPI 加密，存在 `%APPDATA%\video-reskin\credentials.json`，只有当前 Windows 用户能解密。也可以用环境变量 `VIDEO_RESKIN_WINKY_KEY` 临时指定 key。

## 接口来源

| 用途 | 接口 |
| --- | --- |
| 登录 | `POST /marauders-map/lumos-auth/refresh`（携带 Cookie `lumos_refresh_token`）→ `lumos_access_token`，请求头为 `Authorization: LumosBearer …` |
| 上传 | `POST /legil/server/input-media-url` → PUT 到 OSS 签名地址 → `POST /legil/server/upload-callback`（`file_id`）→ `POST /legil/server/output-media-url` |
| 视频编辑 | `POST /legil/server/generations/video-to-video`，参数 `generation_mode: video_edit`、`resolution: 1080p`、`model: doubao-seedance-2-5-260628`、`reference_videos`、`reference_images`；轮询 `GET /legil/server/generations/{id}` |
| 图生图（关键帧） | `POST /legil/server/generations/image-to-image`，参数 `model: gpt-image-2.6-sunburst`、`quality: high`、`resolution: 2K` |
| 审片 | `POST https://lumos.diandian.info/winky/gemini/v1/models/gemini-3.8-flash:generateContent`（`inlineData` 视频 + `videoMetadata.fps` + `responseSchema`） |

Lumos 的接口是从网页的实际请求中整理出来的，网页改版后可能需要跟着调整。

## 按需依赖与缓存

| 使用功能 | 自动准备 |
| --- | --- |
| 基础命令 | 私有 Python 3.13.15（uv 0.13.4） |
| 分析、关键帧、渲染、拼接、审片 | NumPy 2.5.3、Pillow 12.3.0、FFmpeg/FFprobe 9.0.2 |
| 扫码登录 | Playwright 1.64.1（使用系统自带的 Edge，不下载浏览器） |

依赖版本和哈希都已锁定。缓存默认放在插件目录内的 `runtime-cache/`，可以用 `VIDEO_RESKIN_CACHE_DIR` 改到其他位置；设置 `VIDEO_RESKIN_OFFLINE=1` 可禁止联网。退出码：`0` 成功；`2` 输入、凭据或规则问题；`3` 运行时或服务故障。
